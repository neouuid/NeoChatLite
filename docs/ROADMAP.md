# 路线图与阶段结论

> 最后更新：2026-10-20

本文记录**已经做完什么**、**还有哪些没做**、以及**为什么停在这里**。
不是愿望清单——没做的每一项都写了触发条件。

## 待验证（需要额外环境）

这些**代码已写但不能在当前环境证明有效**，按价值排序：

| 项 | 需要的环境 | 为什么现在没做 |
|---|---|---|
| 真机录音 / 播放 / 相机 | Android 或 iOS 真机 | 模拟器音频链路不可靠，只能确认真机 |
| 移动端推送 | APNs 证书 / FCM 项目 | 需要开发者账号与真机 |
| Web 端移动浏览器兼容 | 真机浏览器 | 只验证过桌面 Chrome |
| 多实例在线状态准确性 | 两实例 + 真实流量 | 当前 `IsUserOnline` 只看本进程 |
| 性能与容量 | 压测环境 | 没有真实数据量，压测结论不可信 |
| 全文搜索效果 | 10 万+ 消息 | 现在是 `LIKE '%kw%'`，小数据量看不出差异 |

## 明确不做（附理由）

| 项 | 理由 |
|---|---|
| 音视频通话 | 用户已明确排除；信令代码保留但不接入客户端 |
| 微服务拆分 | 聊天写入天然跨模块（消息/未读/提及/会话活跃），拆开就要分布式事务 |
| 对象存储（MinIO/OSS） | 本地磁盘 + 鉴权接口够用，等真要多机部署再说 |
| i18n | 单语言产品，提前做只增加维护成本 |
| 换状态管理框架 | 36 个用例已覆盖状态层，换框架是纯负债 |
| Kubernetes 清单 | 单实例部署够用；多实例方案已文档化，等有需求再写 |

## 技术债（已知且接受）

| 项 | 影响 | 触发修复的条件 |
|---|---|---|
| 限流/登录锁定计数在进程内存 | 多实例下阈值 = 实例数 × 配置值 | 上多实例时换 Redis 计数 |
| 发送队列只在内存 | 进程被杀会丢待发消息 | 需要「离线也能发」时落盘 |
| `LIKE` 搜索 | 数据量大后全表扫 | 单会话消息超过 10 万条 |
| 指标是自定义 JSON | 需手工接入 Prometheus | 需要告警时 |
| 无审计日志 | 踢人、解散群无记录 | 需要合规/追责时 |
| 无内容审核 | 无敏感词/举报 | 需要上架应用商店时 |

## 建议的下一步

按「投入产出比」排序：

1. **真机验收**（1-2 天）：装 APK，跑一遍发送/接收/语音/视频/后台恢复。
   当前所有验证都是桌面与 Web，移动端只验证了「能编译」。
2. **部署一次真实环境**（半天）：按 `docs/部署文档.md` 上线，用真实域名 +
   HTTPS 跑一遍，会暴露反向代理、CORS、WebSocket 升级这类只在真实链路出现的问题。
3. **小规模压测**（半天）：几百并发连接 + 消息广播，验证连接数与内存曲线。
   有了数据再决定要不要做全文索引与 presence。

这三件都不需要写新功能代码，但能验证现有 4 万多行代码真的有价值。
