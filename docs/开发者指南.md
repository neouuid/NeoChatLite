## 概述

本文档为 NeoChat 项目的开发者提供完整的开发指南，包括项目架构、开发流程、代码规范等内容。

### 项目定位

NeoChat 是一款现代化的跨平台即时通讯应用，支持：
- iOS / Android 移动端
- Windows / macOS 桌面端
- WebSocket 实时通信
- 单聊 / 群聊 / 音视频通话

## 项目架构

### 整体架构

```
neochat/
├── backend/                    # 后端 (Go)
│   ├── cmd/api-gateway/        # 应用入口（含路由装配）
│   ├── internal/
│   │   ├── auth/               # 认证、令牌、审批中间件
│   │   ├── user/               # 用户、好友、黑名单
│   │   ├── chat/               # 会话、消息、群组、WebSocket、上传
│   │   └── migrations/         # 版本化迁移（goose + 双方言 SQL）
│   ├── pkg/                    # config / database / redis / response / logger
│   │                           # middleware / broadcast / utils / email / test
│   ├── configs/                # 配置样例
│   ├── docs/                   # swag 生成的 OpenAPI
│   └── Dockerfile
├── client_sdk/dart/            # 由 OpenAPI 生成的 Dart SDK（含 realtime）
├── client_app/                 # Flutter 客户端（六端）
├── docs/                       # 文档索引见 docs/README.md
├── design/                     # 设计稿
├── scripts/                    # E2E 与部署形态验证脚本
└── docker-compose.yml          # Postgres + Redis + 后端
```

### 技术栈

#### 后端
- **语言**: Go 1.24
- **Web 框架**: Gin
- **ORM**: GORM
- **数据库**: PostgreSQL（生产）/ SQLite（测试与本地）
- **缓存与广播**: Redis（缓存 + 跨实例 Pub/Sub）
- **实时通信**: gorilla/websocket
- **认证**: JWT（access/refresh 分离，刷新令牌落库）
- **迁移**: goose（版本化，启动时自动推进）
- **文档**: swaggo（`swag init` → OpenAPI）
- **测试**: testing + testify + miniredis

#### 客户端
- **框架**: Flutter 3.44（Android / iOS / Web / macOS / Windows / Linux）
- **语言**: Dart 3.12
- **状态**: `ChangeNotifier`（`NeoChatSession`，纯 Dart，可单测）
- **网络**: `client_sdk/dart`（自生成，HTTP 走条件导入的 IoTransport / HttpTransport）
- **媒体**: `just_audio`（语音）、`video_player`（视频）、`file_picker`、`record`
- **本地存储**: `shared_preferences`（登录态、消息缓存）

### 开发规范

#### 1. 分层架构

采用标准的三层架构：

```
Handler (HTTP 层)
    ↓
Service (业务逻辑层)
    ↓
Repository (数据访问层)
    ↓
Database
```

#### 2. 代码组织

每个模块包含以下文件：

- `model.go` - 数据模型定义
- `repository.go` - 数据库操作
- `service.go` - 业务逻辑
- `handler.go` - HTTP 处理器
- `middleware.go` - 中间件（如需要）

#### 3. 模型定义

```go
package auth

import (
	"time"
	"github.com/google/uuid"
	"gorm.io/gorm"
)

type VerificationToken struct {
	ID        uuid.UUID      `gorm:"type:uuid;primary_key" json:"id"`
	UserID    uuid.UUID      `gorm:"type:uuid;index;not null" json:"user_id"`
	Token     string         `gorm:"type:varchar(255);uniqueIndex;not null" json:"-"`
	Type      string         `gorm:"type:varchar(50);index;not null" json:"type"`
	ExpiresAt time.Time      `gorm:"index;not null" json:"expires_at"`
	CreatedAt time.Time      `gorm:"index" json:"created_at"`
}

func (v *VerificationToken) BeforeCreate(tx *gorm.DB) error {
	if v.ID == uuid.Nil {
		v.ID = uuid.New()
	}
	return nil
}

func (v *VerificationToken) IsExpired() bool {
	return time.Now().After(v.ExpiresAt)
}
```

#### 4. Repository 层

```go
package auth

import (
	"errors"
	"github.com/google/uuid"
	"gorm.io/gorm"
)

type Repository struct {
	db *gorm.DB
}

func NewRepository(db *gorm.DB) *Repository {
	return &Repository{db: db}
}

func (r *Repository) CreateVerificationToken(token *VerificationToken) error {
	return r.db.Create(token).Error
}

func (r *Repository) GetVerificationToken(token string, tokenType string) (*VerificationToken, error) {
	var vt VerificationToken
	err := r.db.Where("token = ? AND type = ?", token, tokenType).
		First(&vt).Error
	if err != nil {
		return nil, err
	}
	return &vt, nil
}

func (r *Repository) DeleteVerificationToken(id uuid.UUID) error {
	return r.db.Delete(&VerificationToken{ID: id}).Error
}
```

#### 5. Service 层

```go
package auth

import (
	"errors"
	"github.com/google/uuid"
	"github.com/neochat/backend/pkg/config"
	"gorm.io/gorm"
)

type Service struct {
	repo   *Repository
	config *config.Config
}

func NewService(repo *Repository, cfg *config.Config) *Service {
	return &Service{repo: repo, config: cfg}
}

func (s *Service) VerifyEmail(req *VerifyEmailRequest) error {
	vt, err := s.repo.GetVerificationToken(req.Code, TokenTypeEmailVerification)
	if err != nil {
		if errors.Is(err, gorm.ErrRecordNotFound) {
			return errors.New("invalid or expired code")
		}
		return err
	}

	if vt.IsExpired() {
		return errors.New("code has expired")
	}

	return s.repo.DeleteVerificationToken(vt.ID)
}
```

#### 6. Handler 层

```go
package auth

import (
	"net/http"
	"github.com/gin-gonic/gin"
	"github.com/neochat/backend/pkg/response"
)

type Handler struct {
	service *Service
}

func NewHandler(service *Service) *Handler {
	return &Handler{service: service}
}

func (h *Handler) VerifyEmail(c *gin.Context) {
	var req VerifyEmailRequest
	if err := c.ShouldBindJSON(&req); err != nil {
		response.Error(c, http.StatusBadRequest, "invalid_request", "请求参数错误")
		return
	}

	if err := h.service.VerifyEmail(&req); err != nil {
		response.Error(c, http.StatusBadRequest, "verify_failed", err.Error())
		return
	}

	response.Success(c, nil, "邮箱验证成功")
}
```

### API 响应规范

使用统一的响应格式：

```go
// 成功响应
response.Success(c, data, message)

// 错误响应
response.Error(c, statusCode, errorCode, message)
```

响应格式：

```json
{
  "success": true,
  "data": { ... },
  "message": "操作成功"
}
```

```json
{
  "success": false,
  "error": "invalid_request",
  "message": "请求参数错误"
}
```

### 添加新模块

#### 步骤

1. **创建模块目录**
   ```bash
   mkdir internal/mymodule
   ```

2. **创建模型** (`model.go`)
   - 定义数据结构
   - 添加 GORM 标签
   - 添加 `BeforeCreate` 钩子（如需要）

3. **创建 Repository** (`repository.go`)
   - 定义 Repository 结构体
   - 实现 `NewRepository` 函数
   - 添加 CRUD 方法

4. **创建 Service** (`service.go`)
   - 定义 Service 结构体
   - 实现 `NewService` 函数
   - 添加业务逻辑方法

5. **创建 Handler** (`handler.go`)
   - 定义 Handler 结构体
   - 实现 `NewHandler` 函数
   - 添加 HTTP 处理器

6. **在 main.go 中注册路由**
   - 初始化各层
   - 设置路由

### 数据库迁移

添加新模型后，GORM 会自动迁移：

新增/修改表结构需要写迁移文件（不再是改模型后靠 AutoMigrate 自动同步）：

```
backend/internal/migrations/sql/postgres/00002_xxx.sql
backend/internal/migrations/sql/sqlite/00002_xxx.sql
```

两个方言的语义必须一致，格式与验证方式见 [MIGRATIONS.md](MIGRATIONS.md)。
测试中仍可用 `AutoMigrate` 快速建表（只建该测试关心的模型）。

## 客户端开发（Flutter）

### 项目结构

```
client_app/lib/
├── main.dart              # 启动：恢复登录态 → 会话列表 / 登录页
├── state/
│   ├── session.dart       # 全局状态与全部 API 操作（纯 Dart，可单测）
│   ├── token_store.dart   # 登录态持久化（shared_preferences）
│   ├── message_cache.dart # 每会话最近 200 条消息缓存
│   └── refreshing_transport.dart  # 401 自动刷新并重放
├── pages/                 # 11 个页面
│   ├── login_page.dart / register_page.dart
│   ├── conversations_page.dart / chat_page.dart
│   ├── contacts_page.dart / create_group_page.dart / group_info_page.dart
│   ├── profile_page.dart / user_profile_page.dart
│   └── search_page.dart / mentions_page.dart / favorites_page.dart
└── widgets/
    ├── audio_bubble.dart  # 语音消息（just_audio）
    └── video_bubble.dart  # 视频消息（video_player）
```

SDK 在 `client_sdk/dart/`：由 `swagger.json` 生成，**不要手改 `api_client.dart` / `models.dart`**。

### 状态与数据流

```
UI (Page)
  ↓ 调用
NeoChatSession            ← 唯一状态源（ChangeNotifier）
  ↓ 调用
NeoChatApi (SDK)          ← 自动带 token、401 自动刷新
  ↓
Transport（IoTransport / HttpTransport，按平台条件导入）
```

- 页面不直接持有 HTTP 客户端，全部通过 `session` 调用
- 实时事件：`session.realtimeEvents`（WebSocket），页面自行订阅
- 需要在测试里隔离网络时，给 `NeoChatSession` 注入假的 `NeoChatApi` / `TokenStore` / `Uploader`

### 添加一个页面

1. 在 `lib/pages/` 新建 `xxx_page.dart`，构造函数接收 `NeoChatSession session`
2. 数据操作加到 `session.dart`（不要在页面里直接调 `api`），这样能被单测覆盖
3. 入口挂在 `conversations_page.dart` 的菜单或 `chat_page.dart` 的操作里
4. 在 `test/session_test.dart` 补一条用例（假 API 覆盖对应方法）

### 交互约定

| 场景 | 位置 |
|---|---|
| 长按消息 | 复制 / 回复 / 编辑（自己的文本）/ 收藏 / 转发 / 撤回 |
| 长按会话 | 置顶 / 免打扰 |
| 输入栏 📎 | 图片 / 文件 / 语音 / 视频 |
| 群聊点发送者昵称 | 他人资料页 |

### 平台差异

| 能力 | 说明 |
|---|---|
| 网络 | 桌面/移动用 `dart:io`，Web 用 `package:http`（条件导入，业务代码无分支） |
| 文件访问 | 均走鉴权 URL（`session.fileUrl()` 会拼上 token） |
| 通知 | 仅应用内提醒；系统级推送未实现 |

## 代码规范

### Go 代码规范

#### 命名规范

- **包名**: 小写单词，不使用下划线或驼峰
  ```go
  package auth      // ✅
  package Auth      // ❌
  package auth_svc  // ❌
  ```

- **函数名**: 导出使用驼峰，私有使用小写
  ```go
  func NewService()   // ✅ 导出
  func doSomething()  // ✅ 私有
  ```

- **常量**: 驼峰或大写带下划线
  ```go
  const TokenTypeEmailVerification = "email_verification"  // ✅
  const MAX_SIZE = 100  // ✅
  ```

#### 格式化

使用 `gofmt` 自动格式化：

```bash
gofmt -w .
```

#### 注释

- 导出函数必须添加注释
- 注释以名称开头，说明功能
  ```go
  // NewService 创建认证服务实例
  func NewService(repo *Repository, cfg *config.Config) *Service {
  ```

### Dart / Flutter 代码规范

#### 命名

- 类 / 枚举：`UpperCamelCase`
- 变量 / 方法：`lowerCamelCase`
- 常量：`lowerCamelCase`（Dart 惯例，不用 UPPER_SNAKE）
- 文件名：`snake_case.dart`

#### 格式化与静态检查

```bash
cd client_app && dart format lib test && flutter analyze
cd client_sdk/dart && dart format lib tool && dart analyze
```

`flutter analyze` 必须零告警；`use_build_context_synchronously` 之类的 lint
不要用 `// ignore` 绕过，改成 `if (!context.mounted) return;`。

#### 异步与错误处理

- `await` 之后使用 `BuildContext` 前必须检查 `context.mounted`
- 网络错误统一在 `session` 层转成 `session.error` 并 `notifyListeners()`
- 不要吞异常：至少 `debugPrint` 或写入 `session.error`

#### 资源释放

`StatefulWidget` 里创建的 `TextEditingController` / `StreamSubscription` /
播放器实例，必须在 `dispose()` 中释放。

## Git 工作流

### 分支策略

- `main` - 主分支，稳定版本
- `develop` - 开发分支
- `feature/*` - 功能分支
- `bugfix/*` - 修复分支
- `hotfix/*` - 紧急修复

### 提交规范

使用约定式提交格式：

```
<type>(<scope>): <subject>

<body>

<footer>
```

Type 类型：
- `feat` - 新功能
- `fix` - 修复 bug
- `docs` - 文档更新
- `style` - 代码格式调整
- `refactor` - 重构
- `test` - 测试相关
- `chore` - 构建/工具相关

示例：

```bash
git commit -m "feat(auth): 添加邮箱验证功能

- 添加 VerificationToken 模型
- 添加邮箱验证 API 端点
- 添加邮件发送服务"
```

### 开发流程

1. **创建功能分支**
   ```bash
   git checkout -b feature/my-new-feature
   ```

2. **开发并提交**
   ```bash
   git add .
   git commit -m "feat: 添加新功能"
   ```

3. **推送到远程**
   ```bash
   git push -u origin feature/my-new-feature
   ```

4. **创建 Pull Request**

5. **代码审查和合并**

## 常见问题

### 后端

**Q: 如何添加新的 API 端点？**

A:
1. 在 handler.go 中添加处理函数
2. 在 main.go 的路由中注册
3. 在 service.go 中添加业务逻辑
4. 在 repository.go 中添加数据访问（如需要）

**Q: 数据库迁移失败怎么办？**

A:
1. 检查模型定义是否正确
2. 检查数据库连接
3. 删除数据库重新创建（开发环境）
4. 手动编写迁移 SQL

**Q: 如何调试 WebSocket？**

A:
1. 使用浏览器的开发者工具查看 WebSocket 连接
2. 使用 `wscat` 命令行工具测试
3. 添加日志调试消息

### 客户端

**Q: Flutter 构建缓存异常？**

A:
```bash
cd client_app && flutter clean && flutter pub get
```

**Q: 依赖拉取慢 / 失败？**

A: 设置国内镜像后重试：
```bash
export PUB_HOSTED_URL=https://pub.flutter-io.cn
export FLUTTER_STORAGE_BASE_URL=https://storage.flutter-io.cn
flutter pub get
```

**Q: 分析器报 use_build_context_synchronously？**

A: 在 `await` 之后使用 `context` 前加 `if (!context.mounted) return;`，
不要用 `// ignore` 绕过。
